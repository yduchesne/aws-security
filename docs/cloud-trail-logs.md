# Lab CloudTrail S3 Data-Event Logging

## Purpose

This document defines the project-owned evidence path for S3 object data events
generated by security exercises. It is separate from the AWS Control
Tower-managed organization trail and centralized logging buckets.

## Architecture

```text
Management account
  └── aws-security-lab-s3-data-events organization trail
        └── S3 object data events for aws-security-week2-* buckets
              └── Dedicated bucket in Log Archive
                    └── Read-only Dev Lab and Test Lab evidence prefixes
```

Terraform ownership is isolated in [`terraform/lab/evidence/`](../terraform/lab/evidence/):

- The management-account provider creates the customer-managed organization
  trail.
- The Log Archive provider assumes `AWSControlTowerExecution` and creates the
  dedicated evidence bucket and policy.
- `terraform/identity_center/workload_access/` owns the additional read-only
  `WorkloadLabAdministrator` identity-policy statements.
- Control Tower continues to own its trail, roles, and logging buckets.

## Deployment order

```text
terraform/bootstrap
  → terraform/identity_center
  → AFT platform and Dev/Test Lab accounts
  → terraform/lab/foundation
  → terraform/identity_center/workload_access
  → terraform/lab/evidence
  → terraform/lab/week2/baseline
  → Week 2 exercises
```

The lab evidence root requires an `ACTIVE`, `IN_SYNC` landing zone and the
completed Log Archive account. It is launched initially with the temporary
`ct-bootstrap` profile. The Log Archive provider assumes the existing
Control Tower execution role; exercise users never receive that role.

The bucket name is intentionally deterministic:

```text
aws-security-lab-evidence-<MANAGEMENT_ACCOUNT_ID>
```

This allows the workload permission set to reference the future bucket ARN
without taking ownership of the bucket.

## Trail scope

The trail is:

- Customer-managed and project-owned.
- An organization trail.
- Multi-Region.
- S3-only, with no CloudWatch Logs destination.
- Configured with log-file validation.
- Restricted to `Data` events for `AWS::S3::Object` resources whose ARNs begin
  with the configured `lab_bucket_name_prefix`.
- Configured without management events, which remain the responsibility of the
  Control Tower-managed trail.
- Configured with `include_global_service_events = true` because AWS requires
  that setting for multi-Region trails. The advanced selector still admits only
  S3 object data events, so global-service management events are not duplicated.

The default exercise bucket prefix is environment-specific and should resemble:

```text
aws-security-week2-<MANAGEMENT_ACCOUNT_ID>-
```

Restricting the selector avoids collecting unrelated organization-wide S3 data
events and limits CloudTrail data-event charges. The selector records both read
and write object data events under the approved prefix so exercises can retain
success and denial evidence for `GetObject`, `PutObject`, `DeleteObject`, and
related object operations.

## Evidence bucket controls

The dedicated Log Archive bucket uses:

- S3 Block Public Access.
- Bucket-owner-enforced Object Ownership.
- Versioning.
- SSE-S3 default encryption.
- A lifecycle rule for current versions, noncurrent versions, and incomplete
  multipart uploads.
- A TLS-only explicit deny.
- CloudTrail delivery permissions constrained by the exact trail ARN, covering
  both the management-account prefix validated by `CreateTrail` and the
  organization prefix used for member-account log delivery.
- Per-lab-account read-only statements constrained to the expected IAM Identity
  Center role ARN pattern.
- An explicit mutation deny for those lab role patterns, preserving only the
  approved bucket-location, listing, object-read, and object-version-read APIs.

The bucket deliberately does not use the mutable `aws-security-week2-` prefix.
`WorkloadLabAdministrator` can administer disposable exercise buckets under
that prefix, but receives only `GetBucketLocation`, constrained `ListBucket`,
`GetObject`, and `GetObjectVersion` for the evidence bucket.

SSE-S3 is intentional for the initial design. It avoids granting cross-account
KMS decryption to temporary lab users. If evidence classification later
requires a customer-managed KMS key, update the key policy, identity policies,
cost analysis, and operational documentation together.

## Log object layout

Organization-trail objects are delivered under prefixes resembling:

```text
s3://<EVIDENCE_BUCKET>/AWSLogs/<ORGANIZATION_ID>/<ACCOUNT_ID>/CloudTrail/<REGION>/YYYY/MM/DD/
```

Digest files used by log-file validation are delivered under corresponding
`CloudTrail-Digest` prefixes.

The Dev Lab role can read only the Dev Lab account prefix. The Test Lab role can
read only the Test Lab account prefix. Because the current Identity Center lab
group is assigned to both accounts, a group member may select each account
session and thereby read both prefixes. Strict user-to-account separation would
require separate groups and assignments.

## Lab-user access

Lab users remain in their Dev Lab or Test Lab
`WorkloadLabAdministrator` sessions. They do not receive a Log Archive account
assignment.

The permission set provides read-only identity permissions to the expected
account prefixes. The evidence bucket policy separately requires
`aws:PrincipalArn` to match:

```text
arn:aws:iam::<LAB_ACCOUNT_ID>:role/aws-reserved/sso.amazonaws.com/<HOME_REGION>/AWSReservedSSO_WorkloadLabAdministrator_*
```

For an IAM Identity Center instance in `us-east-1`, the Region component is
omitted from the IAM role path, matching AWS's role-path convention.

Both the identity policy and bucket policy must allow a request. The wildcard
matches only the generated permission-set role suffix; it does not grant all
roles in the account.

## Retrieving evidence

Obtain the bucket and account prefix from Terraform:

```bash
terraform -chdir=terraform/lab/evidence output -raw evidence_bucket_name
terraform -chdir=terraform/lab/evidence output -json lab_evidence_prefixes
```

After CloudTrail delivery, a lab user can list the prefix corresponding to the
active account session:

```bash
aws s3 ls \
  "s3://<EVIDENCE_BUCKET>/AWSLogs/<ORGANIZATION_ID>/<LAB_ACCOUNT_ID>/CloudTrail/" \
  --profile "$TF_VAR_source_aws_profile" \
  --recursive
```

CloudTrail delivery is not instantaneous. Wait several minutes before treating
an empty prefix as a telemetry issue. Download only the relevant compressed log
objects to a protected temporary directory, inspect `.Records[]`, and remove
local copies after preserving approved redacted evidence.

Standard CloudTrail Event history does not return S3 object data events. These
objects are the authoritative data-event source for this design.

## Cost and security implications

The project incurs CloudTrail data-event charges and S3 request and storage
charges. Cost is controlled through the resource-prefix selector and finite
retention. Broadening the selector to all S3 buckets requires explicit
architecture and cost review.

CloudTrail logs can expose principal ARNs, role-session names, source IPs,
resource names, object keys, request parameters, and authorization errors.
Evidence access is therefore temporary, attributable, and read-only. Do not
commit raw logs to source control or include credentials and sensitive request
fields in retained exercise evidence.

## Destruction

Unlike foundational Control Tower logging, this lab evidence infrastructure is
destructible. The root intentionally has no `prevent_destroy`, and the bucket
uses `force_destroy = true`.

Review first:

```bash
terraform -chdir=terraform/lab/evidence plan -destroy
```

Then destroy when explicitly approved:

```bash
terraform -chdir=terraform/lab/evidence apply -destroy
```

This removes the organization trail, bucket policy, bucket, all object versions,
and all unexported evidence. Preserve any required evidence before approval.
Destroying this root does not modify or destroy the Control Tower-managed trail
or its centralized logging buckets.

## Verification

After apply, verify:

1. The Control Tower landing zone remains `ACTIVE` and `IN_SYNC`.
2. The new trail is an organization, multi-Region trail with no CloudWatch Logs
   destination.
3. Its advanced selector includes only the approved lab S3 object prefix.
4. The evidence bucket is in the Log Archive account.
5. A controlled S3 object request produces a delivered log object.
6. The corresponding lab account session can read its prefix.
7. The session cannot write or delete evidence or list another account prefix.
8. A subsequent Terraform plan reports no changes.
